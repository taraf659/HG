رفع ملف مبيعات ← تنظيف تلقائي ← 5 مؤشرات ← سؤال واحد: «ليش انخفضت أرباحي؟»

## التشغيل
```bash
pip install -r requirements.txt
python make_sample.py            # ملف تجريبي لمقهى (اختياري)
export GEMINI_API_KEY=...        # اختياري؛ بدونه يعمل شرح بقالب جاهز
streamlit run app.py
python tests/test_pipeline.py    # أو: pytest
```

## البنية
| ملف | دوره |
|---|---|
| `cleaning.py` | توحيد أسماء الأعمدة (عربي/إنجليزي)، الأرقام العربية، التواريخ، حذف التكرار، تقرير بكل إجراء |
| `analytics.py` | **كل الأرقام هنا بـ Pandas**: المؤشرات، مقارنة آخر فترتين كاملتين، أثر الكمية وأثر السعر لكل منتج |
| `advisor.py` | Gemini يشرح الحقائق فقط + فحص آلي يكشف أي رقم في الشرح لا يطابق الحسابات |
| `app.py` | واجهة Streamlit عربية |

## القرارات التصميمية
- **الحقائق ثم الشرح**: النموذج يستلم JSON جاهزًا ولا يحسب. وإن ذكر رقمًا غير موجود تظهر تحذيرة.
- **الفترة غير المكتملة** تُستبعد من المقارنة (شهر ناقص يعطي «هبوطًا» وهميًا).
- أثر الكمية + أثر السعر = التغيّر الكلي لكل منتج (يتحقق منه الاختبار).
- عمود `التكلفة` يُفترض أنه **إجمالي تكلفة السطر** وليس تكلفة الوحدة.
- اسم النموذج الافتراضي `gemini-2.5-flash`؛ غيّريه بمتغير `GEMINI_MODEL` إن لزم.

## المرحلة الثانية (مؤجَّلة عمدًا)
إدارة العملاء، التنبيهات، تصدير Power BI، الاشتراكات. لا تبدئي بها قبل أن يدفع أول مستخدم حقيقي.

## الاختبار
```bash
python make_test_files.py        # يولّد test_data/ (8 ملفات فوضوية تحاكي ملفات أصحاب المتاجر)
python tests/test_pipeline.py    # الحسابات والتنظيف الأساسي
python tests/test_scenarios.py   # كل ملف في test_data له توقّع صريح
python cli.py test_data/02_english_xlsx_title_rows_no_cost.xlsx --no-ai
GEMINI_API_KEY=... python evals.py   # يقيس أمانة Gemini: أرقام مختلقة، وإقراره بنقص البيانات
```
عند وصول ملف حقيقي من عميل يفشل فيه التنظيف: أضيفيه (بعد إخفاء البيانات الحساسة) إلى `test_data/` واكتبي له اختبارًا قبل الإصلاح.
